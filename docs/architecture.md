# 架构与工程约定

采用模块化单体和显式依赖注入，单个 Go 服务二进制负责后续业务。`cmd` 处理 CLI及开发工具，`internal/app` 是依赖装配入口，业务模块经 `internal/modules.Registry` 注册。现阶段注册upstreams基础设施模块，游戏业务模块尚未迁移。共享客户端放在pkg，配置和生命周期在internal/integrations装配，后续业务通过明确依赖调用，不通过本机HTTP绕行。

领域内按实际复杂度拆分 domain/application/adapters：领域规则不依赖 HTTP 或数据库驱动，仓储接口定义在使用方，HTTP handler 不直接拼接 SQL。模块公开应用服务，私有数据库表及缓存由模块自己管理，避免旧系统循环依赖。

基础设施由启动参数显式决定，关闭的 PostgreSQL/Redis 不创建连接。数据库默认最多8个连接，Redis默认4个；后续应按负载测量调整。日志直接写标准输出，不在进程内保留无限日志历史。Prometheus 使用每个实例自己的 registry，并以注册路由而非原始 URL 作为标签，防止高基数增长。不得将用户ID、凭证或任意查询参数加入指标标签。

服务具备请求头/读取/写入/空闲超时、请求体上限、panic恢复、请求ID、优雅退出、可选依赖就绪检测。探针仅公开最低限度的状态。未来 SSE/流式接口需在明确路由上设计独立超时和退出语义，不能直接套用目前30秒写超时。

插件采用普通Go包编译注册，不使用平台相关.so。用户新增TS兼容要求后，增加按需独立Node worker作为明确例外，默认关闭；Go宿主负责调度、授权及上游调用，不启动旧机器人或Python。后台任务必须有context、并发和队列上限、取消及等待路径。详见plugins.md。

Go 模板使用 `html/template` 和必要时 `embed`。旧 art-template、脚本和 CSS 只能作为迁移参考：语法、数据模型和 CSP 必须适配。HTML 图片渲染可后续通过 Go 控制可选 Chromium；浏览器应有固定工作池、超时、内存回收和队列上限。当前工程没有浏览器或 Node 运行时依赖。

HTTP 客户端在模块边界集中管理，复用连接池，限制响应大小与并发；不对有副作用请求盲目重试。跨账号操作需要所有者授权，通行证凭证只能由所属 Provider 读取和续期。敏感材料通过进程环境和专用密钥系统注入，不向公开 API 或日志暴露。

数据库迁移和数据导入独立于服务启动。先对旧 Prisma schema、数据版本、加密算法和事件契约建立映射，再选择适合的 SQL 仓储实现，避免为“全面工程化”先创建与旧业务不一致的新业务表。

开发工具固定版本：Air v1.67.4、golangci-lint v2.15.0、govulncheck v1.9.0。服务依赖固定在 go.mod/go.sum；CI 检查格式、依赖完整性、vet、测试、竞态、构建、静态分析、漏洞及独立服务集成测试。当前已执行和未执行的项目以 verification.md 为准，CI 配置存在不代表云端运行已通过。
