# 千寻官方文档勘误和兼容记录

依据2026-10-27抓取的官方快照 `official.json`，原文保持不变。SDK不会接受非法JSON来掩盖上游错误；测试在确认原示例严格解析失败后，单独构造修正逗号后的派生样本验证字段。

| 原文位置 | 发现的问题 | 本实现处理 |
|---|---|---|
| 直连authExpire事件示例 | 出现重复逗号 `,,` | 原样保存；运行时仍要求合法JSON |
| 框架groupMemberChanges的新版本示例 | inviterWxid行出现尾逗号 | 派生测试只去掉尾逗号；保留InviterWXID字段 |
| 直连groupMemberChanges的新版本示例 | 同样出现尾逗号 | 与框架保持一致 |

其他容易误解但不应“修正”的协议差异：注入成功时WXID允许为空；框架10014的data直接是账号对象且type为0/1；10007支付通知的内层type仍是recvMsg；订单字段沿用官方 `transcationid` 拼写；不同版本数字字段会以字符串或数字返回，因此使用Scalar；框架和直连的killWeChat请求结构不同。

具体页面URL、完整字段说明及全部版本示例可在official.json按name检索。本次逐项测试覆盖全部97项RPC和2项流式下载，并用事件正文中的合法样本、3个勘误派生样本验证解码，不将文档错误等同于线上服务行为。
