# 旧项目对外 HTTP 接口的用途

本轮按要求不封装这些旧路由。以下依据旧项目当前源码核对用途，不把旧OpenAPI文件的数量当作当前完整运行时数量。

## 管理控制台和数据库服务

主要入口为旧项目 `src/database/rest-server.ts`，默认端口8787，使用旧项目API key。它同时承担数据库管理、控制台后端和部分操作代理，名称并不只代表数据库。

| 旧路由/接口族 | 有什么用 | 调用方 | 后续重构建议 |
|---|---|---|---|
| `GET /api/v1/health` | 判断旧HTTP服务是否存活 | 控制台、部署探针 | 新工程已有自己的healthz/readyz，无须把旧服务再包一层 |
| `GET /api/v1/meta/database` | 枚举旧数据库实体、字段和复合主键 | 管理工具、旧Apifox | 迁移数据时作为参考，不等于新工程数据库设计 |
| `/api/v1/<实体>`、`/api/v1/<实体>/<主键...>` | 实体列表、创建、读取、修改、删除；包含账号、群、权限、文档及旧插件持久化数据 | 受管理密钥保护的数据库工具 | 待业务迁移后按领域定义管理接口，不预先暴露新数据库全表CRUD |
| `GET /api/v1/meta/runtime-status` | 汇总旧进程、队列、插件、外部依赖等真实运行状态 | 图形控制台 | 等Go业务模块具备真实状态后逐项提供，不能返回模拟健康 |
| `GET /api/v1/meta/runtime-logs` | 按通道和数量读取旧运行日志 | 控制台日志面板 | 新工程先使用结构化标准输出；日志检索另按运维需要设计 |
| `GET /api/v1/meta/config` | 读取机器人、插件、群列表及实际生效开关的配置摘要 | 群管理控制台 | 等配置与权限业务迁移后再实现管理视图；不是修改全部配置的任意入口 |
| `PATCH /api/v1/meta/groups/<群ID>` | 调整某个群的机器人总开关、插件开关或功能开关 | 群管理控制台 | 保留群级权限和配置持久化语义后再迁移 |
| `/api/v1/meta/api-hub`、`/health`、`/metrics` | 查看旧API Hub中注册的客户端/服务、健康检查和调用统计 | 控制台、诊断工具 | 新工程提供独立SDK目录与资源统计，后续按真实业务补充观测 |
| `/api/v1/meta/render/puppeteer/{health,metrics,benchmark}` | 查看旧Chromium页面池与渲染队列状态，或显式运行性能基准 | 运维和渲染诊断 | 渲染模块迁移时单独实现；基准操作有资源消耗，不作为普通探针反复调用 |
| `POST /api/v1/qx/<操作>` | 让外部调用方借旧机器人转发千寻RPC，目标机器人可通过请求头选择 | 旧控制台、第三方脚本 | 本轮直接提供Go SDK和有界网关，不重新开放旧HTTP代理入口 |
| `GET /api/v1/qx/downloadFile` | 借旧机器人下载千寻侧文件，旧实现会整段缓冲 | 需要取图片/附件的旧调用方 | 新SDK提供有界流式Writer下载；未来如有网页需求再定义授权的下载路由 |
| `/api/v1/meta/ai/stickers`及其子资源 | AI素材/表情包列表、上传、标签、文件读取、删除等管理 | 独立表情包管理WebUI | 随AI素材模块迁移，不属于米哈游或千寻上游API |

数据库接口的分页、主键、JSON/二进制序列化和敏感字段处理由旧仓储实现决定。新工程目前只保留迁移参考，没有连接旧数据库，也没有开放这些旧路由。

## 账号绑定与通行证网页

主要入口为旧项目 `src/plugins/mihoyo-bind/bind-server.ts`，旧默认端口8765；通过一次性密钥和浏览器会话授权，提供用户可打开的网页及其配套JSON接口。

| 旧路由/接口族 | 有什么用 | 本轮边界 |
|---|---|---|
| `/wxid`、`/wxid/access`、`/wxid/status`、`/wxid/state` | 打开绑定页、验证访问密钥、查询登录/绑定进度、读取通行证状态 | 网页和站内会话暂不实现；本轮封装的是它们背后需要调用的上游登录/验证API |
| `/wxid/login`、`/wxid/har`、`/wxid/uid` | 通过账号登录、已有抓包凭证或公开UID关联游戏账号 | 上游RSA登录、Token验证/交换、Cookie绑定校验、公开展柜API已单独封装；本轮不提供HAR上传或旧网页入口 |
| `/wxid/switch`、`/wxid/provider` | 切换本地绑定账号和绑定服务提供者 | 属于本地账号管理与Provider授权业务，待持久化/权限层迁移 |
| `/wxid/<provider>[/action]` | 将森空岛、鸣潮等其他Provider的绑定流程挂到统一入口 | 不是HoYoLAB本身的API；按对应业务另行迁移 |
| `/wxid/hub[/accounts|panels|endfield]`、`/wxid/avatar` | 用户个人中心、账号摘要、面板与终末地数据聚合、头像 | 属于新界面/聚合业务，不能把上游原始凭证直接返回给页面 |
| `/wxid/uigf/{import,analysis}` | UIGF抽卡数据导入和分析 | 是本地导入/统计业务，不是米哈游上游抽卡接口 |
| `/wxid/assets/<文件>` | 为旧通行证页面提供CSS、脚本、图片等静态资源 | 模板/CSP/资源迁移时再实现；SDK不承载旧前端脚本 |
| `/wxid/public/team-presets/...` | 原神队伍预设网页及相关操作 | 对应本地队伍管理与伤害计算业务，暂不迁移 |
| `/wxid/public/wuwa-panels/...` | 鸣潮面板公共页面 | 属于鸣潮模块，暂不迁移 |

本轮Go `LoginApp` / `LoginWeb` / `ExchangeSToken` / `RefreshCredentials` / `BindCookie` 是服务端调用工具：不创建浏览器登录页面，不生成旧站点链接，不把结果自动写入数据库。凭证存储、微信所有者关联和界面授权将由后续Provider模块完成。

## 其他独立网页服务

| 服务 | 旧接口用途 | 本轮处理 |
|---|---|---|
| PokeMMO活动网页（`src/plugins/pokemmo-guild/activity-web.ts`） | 活动列表/详情、按昵称搜索成员、`/activity/<id>/api/search`与`/api/register`在线报名 | 工会业务后续迁移，不包装成米哈游/千寻SDK |
| 表情包管理独立站（`src/services/sticker-manager-web-service.ts`） | 托管素材管理页面，并只代理允许的表情包API到旧主服务 | 暂不迁移页面或代理 |
| 管理控制台前端工程（`group-bot-console`） | 展示旧主服务的真实状态、日志及群管理，前端/代理不是另一套机器人业务 | 等Go管理接口稳定后再适配 |
| 一起听云服务（`together-listen-cloud`，旧默认8788） | `POST /api/v1/rooms`创建房间；`/rooms/...`提供播放页面、成员/播放状态及SSE同步 | 是独立音乐会话服务，暂不迁移，不混入新上游网关 |

千寻回调是上游向机器人推送事件的入口，本轮提供了新的 `/callbacks/qianxun` 和可复用处理器；它使用独立token。这个入口服务于新事件SDK，并没有恢复旧管理API。

本说明中的旧端口是源码默认值，不代表当前生产进程正在监听。源材料和旧项目始终只读，本轮没有为核对用途启动旧服务或读取真实账号数据。
